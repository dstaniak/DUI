DUI — class and flow map

Current state: an educational game with a convoy of police cars turning smoothly behind the player's red car and hopping over curbs, randomly selected beer, vodka, powder, mushrooms, and sausages, foam splashes, shaking after vodka, acceleration and effect suppression after powder, and a rainbow, reversed controls, and slowdown after mushrooms, set in a parking lot outside a shop, with no main menu. Retro presentation: 1280×720, UI with a screen font and an orange-and-yellow C64 palette, artwork colors, and two-color patterns in selected texture shadows. A working DesktopGL host, a separate reusable MonoGameLibrary, game and desktop assemblies, and basic pointer/touch input. CI prepares desktop packages for four architecture/OS combinations. Mobile hosts are not planned.

Building and distribution

Desktop builds → model tests on Windows, Linux, and macOS Intel/Apple Silicon → publishing four variants on Windows → packaging on target systems (optionally Developer ID → notarization → ticket stapling on Mac) → validation of extracted archives → SHA-256 and artifacts retained for 30 days. Push of a vA.B.C.D tag → draft GitHub Release → manual game checks and publication → manual upload to itch.io.

release.py publishes self-contained .NET 10 with DesktopGL assets, checks the complete MGCB content, native libraries, runtime, architecture, and execution permissions. macOS gets DUI.app with assets in Contents/Resources/Content and an ad hoc signature by default. After Developer ID setup, tags with MACOS_SIGNING_ENABLED enabled or manual sign_macos runs sign both Mac packages, require Apple's acceptance, staple the ticket, and recreate the ZIP. A failure stops the release, with no fallback to ad hoc. Signing setup imports secrets into the runner's temporary keychain; the workflow removes it even after a failure. Release tests check version names, assets, architecture, and the complete archive set before checksums are created. Signing tests check required options, termination after Apple's rejection or tool errors, and ticket stapling only after acceptance; they do not replace actual notarization. A pull request runs only tests; a push to main or a manual run also creates packages. The workflow does not bump the project version or overwrite published Releases. The release guide describes downloads, graphics/audio checks, macOS limitations, and publishing to itch.io. This does not change gameplay flows.

Startup and state ownership

Program → DuiGame → Core.ChangeScene → GameScene.Initialize → playfield and gameplay.

Project references form DUI.Desktop → DUI.Game → MonoGameLibrary. The reusable library contains no DUI or Gum dependencies. DUI.Desktop builds the game content with DesktopGL; DUI.Game owns game-specific presentation settings and effects. Core owns the scene, services, and Debug ImGui renderer. DuiGame owns RetroRenderer, which disposes its two 1280×720 buffers (world and transparent UI) and the watched doubleVisionEffect and rainbowEffect materials. GameScene disposes its watched grayscale material. Each watched asset owns a separate ContentManager, so its replacement cannot invalidate another material. GameScene owns active gameplay time PlayTime, session state, alcohol level in per mille (decimal), ParkingLot, CarConvoy, Pickup, BeerBurst, ScreenShake, PowerupEffects, and the UI. PickupRules defines PickupType selection and effects. ParkingLot owns the tilemap, storefront, ParkingGeometry, grass island geometry, and a one-pixel grid texture. ParkingLot.Dispose releases the grid texture; the scene's ContentManager releases the artwork textures. ConvoyMovement owns the queue, car poses, and simulation time; ConvoyTrail stores a bounded path history. CarConvoy owns the model, player and police car sprites, PoliceLightbar, and a CarHop state for each car; CarSway adds gentle swaying. CarHop detects the front entering an island and calculates scale and lift; GameScene.Score reads the score from CarConvoy.SegmentCount (head and tail). The UI presents it through ScoreStars, displays the alcohol level separately, and emits intents.

Shader development and debugging

Debug Program → ContentManagerExtensions.StartContentWatcherTask → ContentWatcher → dotnet watch → BuildShaderContent → compiled XNB files → Core.Update → Material.UpdateWatchedMaterials → WatchedAsset.TryRefresh → parameter transfer.

F12 toggles the registered s_debugMaterials windows for grayscale, double vision, and rainbow. Override values freezes game-driven numeric setters; float and vector controls permit negative values. Texture previews reuse bindings and preserve aspect ratio. Gameplay still decides whether each effect runs. Core starts the ImGui frame before scene input. GameController discards captured keyboard/pointer input, and GameScene skips Gum interaction while the inspector captures input. Core draws the windows after DuiGame.DrawScene presents both world and UI, so shaders and shake cannot affect the inspector.

Each Material owns a WatchedAsset and isolated ContentManager. At most every 500 ms, a changed XNB is loaded into a candidate manager. Invalid or concurrently changing files keep the previous shader alive; LastReloadError appears in the inspector. After a successful load, compatible parameters and texture bindings transfer, the cache follows the new interface, and the old manager is disposed. Material.Dispose removes both registry entries and releases resources. The renderer owns its font, buffers, BasicEffect, text-input subscription, and native ImGui context; game texture previews are borrowed. Watcher disposal terminates its child process tree. Release starts no watcher or ImGui. The --no-reload argument disables automatic rebuilding in Debug.

User flows and relationships

  1. Turning: Core → InputManager; GameScene → GameController.Update/TryReadDirection (keyboard, controller, and SwipeTracker) → PowerupEffects.MapDirection → CarConvoy.QueueDirection → ConvoyMovement.QueueDirection. DuiGame.Initialize connects GameController to GameWindow.KeyDown/KeyUp, and UnloadContent detaches the events. KeyboardSteering buffers up to eight arrow/WASD presses in event order, including brief presses released before the frame. Holding a key does not emit repeats. GameScene reads all commands before movement and maps each through PowerupEffects; controller or gesture input is read after the keyboard buffer. The movement model still accepts only two pending turns. ConvoyMovement snaps the starting position to the center of an 80×80 tile. Straight sections follow row and column axes. The first pending turn starts at the nearest tile edge ahead of the car. TurnGraceDistance allows a turn to start immediately up to 20 px past the edge (50 ms at normal speed); later commands wait for the next edge. A normal arc has a radius of 40 px. For late input, the radius decreases by the overshoot distance, to a minimum of 20 px. The arc starts at the current position and ends tangent to the correct axis, without moving backward, teleporting, or rewriting the trail. The car travels at 400 px/s (480 after powder, 200 after a mushroom, 240 with both), so a 90° turn takes about 157 ms of simulation time. Position follows arc length, and orientation follows the tangent. The arc endpoint is calculated exactly, without accumulating error over successive turns. A turn that has started always finishes. AdvanceHead splits the 5 ms substep at arc/straight boundaries and records junctions in the trail so interpolation does not cut corners. The queue holds two pending turns; direction is compared against the last target. Repeated headings, 180° reversals, invalid directions, and overflow are rejected. The sequence “right → down → left” changes rows by exactly 80 px; after a tighter arc, a short straight section reaches the next turning point. ConvoyTrail records the head's CarPose; each segment samples the same trail another 80 px earlier. CarConvoy.Draw → ConvoyMovement.GetRenderPose interpolates the pose between states. CarSway.GetPose adds ±1.5 px displacement and ±2° rotation; phase depends on distance, and the cycle corresponds to 1.2 s of convoy simulation. Growth retrieves an older pose, extending missing history backward along the oldest tangent without moving existing cars.
  2. Police cars: GameScene.LoadContent loads car.png and police-car.png. CarConvoy.Draw selects the red car for index 0 and a police car for each tail segment. PoliceLightbar draws the lightbar on the police car roof at local point (−6, 0). Two light states — bright blue (#2068FF) and red (#FF3030) — alternate every 250 ms according to RenderTime. Two opaque 8×12 lamps have small 2×2 highlights, and a black 10×28 frame separates them from the light roof. The color is not lost in white centers or translucent glow. The lights use the lifted center, rotation with sway, and combined terrain and hop scale. Pausing or game over freezes the frame; RETRY resets the time to the blue state. Changing the tail's appearance does not change its movement trail, spacing, or collisions.
  3. Parking lot and grass: ParkingLot loads tilemap-definition.xml with the c64-parking-atlas.png atlas. Two 2×4 islands occupy columns 2–3 and 12–13, rows 3–6. The same rectangles place the tiles, determine scale through GetCarScale, and are exposed as GrassIslands for animation. SmoothStep increases scale from 1 to 1.06 over half a tile's distance from the edge. After each ConvoyMovement.Stepped, CarConvoy updates each car's CarHop. The front is 40 px from the logical center in the direction of travel. Crossing the curb from asphalt to grass starts a hop; entry time is interpolated within the substep. The animation lasts 200 ms: EaseOutCubic lifts the car, EaseInQuad lowers it; the peak is a 1.28 scale multiplier and 12 px lift. CarHop.GetTransform uses RenderTime, keeping it synchronized with the rendered position. An active hop, driving on grass, and leaving the island do not trigger another takeoff; leaving the island allows a new entry. Segments hop in sequence at their own crossings. CarConvoy multiplies the base scale by terrain and hop scales and subtracts lift from Y. Visual effects do not change collisions; pausing freezes them at their current phase. ParkingLot.Draw draws the map, grid, corners, and storefront. DrawGrid places lines every 80 px within the driving bounds (including grass and partial tiles near the fence), shortening vertical sections before the gate. Lines use C64 LightGray (#959595), 1 px thickness, and alpha 0.35, with non-premultiplied RGB for the NonPremultiplied batch. Horizontal sections skip intersections so their alpha does not accumulate with vertical lines. The grid sits below cars and items in the world layer: it shakes and receives shaders along with the playfield, without affecting the UI or collisions. DrawStorefront uses one scale, 160/724, for both axes: the central facade is 480×160, and repeating side sections fill the 1280×160 strip without distorting doors, lettering, or goods. Sections extend outward from the center; partial displays are clipped only at the screen edges. The scene adds cars, the bottle, splashes, and the UI.
  4. Collection: GameScene.CollisionChecks compares the car's Circle with Pickup. CollectPickup first remembers the collected item type. Beer emits BeerBurst, vodka restarts ScreenShake. PowerupEffects.Collect refreshes the powder or mushroom timer, and PickupRules determines the alcohol level change and growth. Beer adds 0.2‰ and a police car; vodka adds 0.4‰ and a police car; a sausage subtracts 0.4‰ down to a minimum of 0‰, without lengthening or shortening the convoy. Powder adds one police car without changing the alcohol level; a mushroom changes neither alcohol level nor length. GameSceneUI.UpdateScoreText displays the number with one decimal place (pl-PL) and the ‰ glyph in the C64 bitmap font. The full text determines the starting position of indicators and stars. The same ScorePermille controls double-vision radius and alpha. GameScene selects a loaded SoundEffect based on the remembered type: beer → burp, vodka → exhale, powder → sniff, mushroom and sausage → eating. AudioController plays the effect before choosing the next item. SpawnPickupAwayFromConvoy selects the opposite side of the parking lot, and PickupRules.ChooseType independently chooses beer 50%, vodka 20%, powder 5%, mushroom 5%, and sausage 20%. Pickup.Spawn sets the artwork, position, new velocity, and resets the pulse. The first item and the item after RETRY are chosen the same way. There is one Pickup at any time.
  5. Vodka and shaking: ScreenShake.Restart starts a new 3-second period. GameScene updates the countdown only while Playing. HorizontalOffset is a sinusoidal ±24 px displacement at 18 cycles per second in the 1280×720 coordinate system. GameScene.Draw passes the offset (zero while powder is active) through transformMatrix to the SpriteBatch for tiles, cars, the item, and particles. DuiGame then switches to a separate UI buffer and calls GameScene.DrawUI. RetroRenderer applies double vision and the rainbow to the world, then overlays the unchanged UI. None of these effects affect the UI. Shaking does not change physics, collision geometry, or UI button hit testing. The exposed edge of the playfield is black. Another vodka refreshes the full duration; beer and snacks do not interrupt it. Pausing and game over freeze the effect; RETRY removes it.
  6. Powerups: GameScene owns PowerupEffects. Collect refreshes the separate powder or mushroom timer to 10 seconds; other items do not change them. Update receives normal Playing time, counts down both timers, and returns convoy movement time. Update splits the frame at both expiry times: powder alone multiplies movement time by 1.2, a mushroom alone by 0.5, and their overlap by 0.6. Remaining time runs at normal speed. The remainder in tenths of a tick is carried over, so dividing frames does not change distance. GameScene → CarConvoy.Update(movementElapsed) → ConvoyMovement.Update. The model preserves substeps, turning curves, the trail, spacing, and interpolation; animations linked to RenderTime follow the convoy clock. PlayTime, powerup timers, shaking, and item movement and pulsing retain their normal speed. MovementSpeedMultiplier uses the same speed constants and describes the state after Collect, Update, or Reset, rather than the average of a frame containing an expiry. GameScene exposes this multiplier to DuiGame, which sets AudioController.SongPlaybackRate after updating the scene. Powder sets VisualEffectsSuppressed: GameScene zeros the visual world offset, and RetroRenderer skips double vision and the rainbow without changing ScorePermille. A mushroom slows movement to 0.5× and sets ControlsReversed; MapDirection negates the combined keyboard, controller, and gesture input result. Zero remains zero; existing turn queue rules still apply. RainbowActive requires an active mushroom and no powder. Powder does not remove reversed controls or the mushroom slowdown (together they give 0.6×), nor does it stop hidden effect timers. After powder expires, effects that are still active become visible. Pausing and losing freeze the timers; RETRY resets them.
  7. Effect indicators: GameScene.DrawUI passes ScreenShake.RemainingTime, PowerupEffects.PowderRemaining, and MushroomRemaining to GameSceneUI.UpdateEffectIndicators. These values are read after movement updates and collection, so indicators do not lag by a frame. Three SpriteRuntime instances use separate white icons of a shot glass, bag, and mushroom, in that order. They have fixed slots of 7×7 UI units (28×28 px), spacing of 3 (12 px), and Y=2.5. The first slot starts 3 units after the text containing the ‰ sign. Positions update with the alcohol counter's width. Remaining time greater than zero enables blinking: 300 ms visible, 300 ms hidden, measured from the start of each effect. During the last second of each effect, the rate increases to 100 ms visible / 100 ms hidden; the phase starts with a visible flash at that second's boundary. There is no second UI timer. Refreshing starts with visibility; expiry and RETRY turn the icon off, while pausing and losing freeze its phase. Powder does not reset timers, so hiding shaking or the rainbow does not remove their indicators. The mushroom still reverses controls. Icons belong to the separate UI and are unaffected by world shaders. White 28×28 textures with binary transparency are built by MGCB with premultiplication and use Gum's normal alpha blending; they do not reuse the colored pickup artwork from the playfield.
  8. Score and stars: ConvoyMovement.Cars.Count → CarConvoy.SegmentCount → GameScene.Score → GameScene.DrawUI → GameSceneUI.UpdateScoreStars → ScoreStars.UpdateScore. The score counts all cars, including the head; there is no separate counter that could drift out of sync. Beer, vodka, and powder add a segment and a point. Sausages and mushrooms change neither length nor score. The alcohol level remains a separate value controlling double vision. Five 28×28 px stars occupy fixed slots after the mushroom, even when effect indicators turn off. Each has an always-visible C64Palette.LightGray layer (#959595, RGB 149,149,149) and a white fill layer. ScoreStars limits the displayed range to 0–84 (without limiting convoy growth). It calculates the fill as floor(segments × 140 / 84) pixel columns, excluding gaps. For successive stars, it clips TextureWidth and sprite width from the right; it does not stretch the texture. One pixel is 0.25 Gum units at zoom 4. A value of 0 gives light gray stars, start/RETRY gives 1 point and the first white column, 42 gives exactly 2.5 stars, and 84 or more fills all five. Updates occur before drawing, after collection and reset. Pausing and losing preserve the score. Stars do not blink and are unaffected by world effects.
  9. Game over: contact between the head's rotated footprint and the fence, gate, or storefront, or a ConvoyMovement.BodyCollision → CarConvoy.BodyCollision → GameScene.GameOver event → a single crash sound and the GAME OVER panel. GameOver runs only when transitioning from Playing, so another collision event does not overlap a second sound. ConvoyCollision checks moving 32 px circles, including between substep endpoints, excluding the head's immediate neighbor. CarConvoy passes the current CarPose to ParkingGeometry.IntersectsBoundary after each substep and raises BoundaryCollision. The 74×36 px car footprint rotates with its heading; its extreme points are compared against fence boundaries. The separate gate rectangle is checked on four axes by ConvoyCollision.IntersectsObstacle, so empty corners of a diagonal car's bounding box do not trigger collisions. Transparent texture margins do not enlarge collisions, allowing the narrow side to pass a wall safely after turning. Both collisions stop the model; GameScene interrupts the update before item movement, collection, and scoring. ParkingGeometry aligns boundaries with the artwork's metal edges, not tile edges: x=46–1234, y=160–666; the storefront occupies the top two rows, the side fences occupy columns 0 and 15, and the bottom fence occupies row 8. At the corners (columns 0 and 15, row 8), L-shaped brackets connect the side fences to the bottom span. The two-tile gate (columns 7–8) stays closed and has a separate footprint at x=560–720, y=654–720. This leaves the asphalt in front of the fence drivable, while the protruding gate does not block the rest of the bottom edge. PickupBounds restricts rectangular item movement and respawning to y=654, before the gate. Grass islands are drivable. RETRY → GameSceneUI.RetryButtonClick → InitializeNewGame: one head (score 1 and initial star fill) and an empty queue, reset time, blue light frame, reset sway phase and hop progress, item position, alcohol level 0,0‰, PlayTime=0, double vision off, ScreenShake.Reset, PowerupEffects.Reset (normal speed and controls), BeerBurst.Clear, and a newly selected random item.
  10. Pause: Escape/Start/Back or PAUSE → GameScene.Pause. RESUME → ResumeButtonClick → Playing state; Escape also resumes. Pausing preserves the score and accepted moves, while ResetInput clears an in-progress gesture and undelivered keyboard events. ResetInput also runs on resume, RETRY, and during GameOver. DuiGame.OnActivated synchronizes held keys with the current state, so a KeyUp lost outside the window does not block a direction. Clicking RESUME or RETRY is not interpreted as a turn. The bottle, particles, and ConvoyMovement update only while Playing, so pausing stops pulsing, splashes, swaying, hops, and police lights. PlayTime also advances only while Playing, so pausing and game over freeze the duplicate view's orbit, rainbow shift, PowerupEffects timers, and ScreenShake shaking.
  11. Audio: DuiGame.LoadContent loads Audio/theme as a SoundEffect (the pydim-byte-hook-620646 track supplied in SourceAssets). Initialize sets SongVolume=0.35 and starts looping through AudioController.PlaySong. AudioController owns a separate music instance, and DuiGame.Update passes MovementSpeedMultiplier to SongPlaybackRate after updating the scene: 1× normally, 1.2× after powder, 0.5× after a mushroom, 0.6× with both. The instance changes Pitch=log2(rate), so tempo and pitch change without restarting or seeking the track. Collection, expiry, and effect refreshes take effect in the same frame; RETRY restores 1× at the current track position. Music and effect volumes are separate; SoundEffectVolume scales effect instances, not the global MasterVolume. MuteAudio mutes both channels, including new effects; UnmuteAudio restores their levels. GameScene.LoadContent loads four collection effects into a PickupType → SoundEffect dictionary and a separate crash; mushrooms and sausages share eat. The scene's ContentManager owns the effects, and the main ContentManager owns the track buffer. Item bounces and UI clicks keep their existing sounds and speed. Normal pausing and GAME OVER leave music playing in the background at the frozen powerup multiplier. AudioController disposes the music instance when replacing the track and during Dispose, before ContentManager releases the buffer.
  12. Application backgrounding: DuiGame.OnDeactivated → GameScene.Pause and AudioController.PauseAudio. Core does not update the scene while inactive. OnActivated resets the elapsed time counter and resumes only paused audio instances, preserving music position and speed; gameplay waits for RESUME. This does not save state if the OS kills the process.
  13. Retro screen: Core.Draw → DuiGame.DrawScene → RetroRenderer.BeginFrame → GameScene.Draw → RetroRenderer.BeginUiFrame → GameScene.DrawUI → RetroRenderer.Present. The scene draws only the world into a 1280×720 buffer. BeginUiFrame switches to a second 1280×720 buffer and clears it to transparent. Gum draws the UI there with a logical 320×180 layout and Camera.Zoom=4. The UI never enters the texture sampled by the shader. The alcohol counter is at (20,2), and PAUSE is 20 units from the right edge, at Y=1 with a height of 10 UI units. Both fit within the 48-pixel bar above the shop sign. GameSceneUI.PositionScoreAccessories positions the three indicator slots and ScoreStars according to the full alcohol text width at FontScale=1; the ‰ sign is a glyph in the same font. A change such as 9,8 → 10,0 moves the entire group. Icons and stars are at Y=2.5. The UI bar is 12 units tall, with a C64Palette.Orange background (#6F4F25), yellow text, and a C64Palette.Yellow border (#B8C76F) of width 1. C64Theme creates RectangleRuntime surfaces without rounded corners, gradients, or antialiasing. Pause and game-over panels are centered, measure 240×70 units, and have a border width of 2. Headings use FontScale=2 (64×64 px characters); other text uses scale 1 (32×32 px). C64Button retains Gum input handling but replaces ButtonVisual children with its own border, background, and text. Enabled uses yellow text on orange; Focused and Highlighted use orange text on yellow; Pushed uses orange on white; Disabled uses light gray on orange. All colors come from C64Theme roles: BackgroundColor, TextColor, AccentColor, PressedColor, MutedColor, and SymbolColor. Changing the assignments and recreating the UI changes the entire theme. All category states are overridden, including HighlightedFocused and DisabledFocused. Panel buttons are centered at the bottom. Clicks and focus retain their existing events. Texture colors, alpha blending, and the pause effect retain their full palettes. There is no screen-wide dithering: two-color patterns are part of the parking lot and storefront artwork. Both 1280×720 buffers are scaled with PointClamp to the same GameDisplay.OutputBounds, which covers the entire window without borders, bars, or playfield cropping. Each axis scales independently; a 16:9 view preserves world proportions. DuiGame passes GameScene.ScorePermille, PlayTime, VisualEffectsSuppressed, and RainbowActive to Present. At 0.0‰ or with active powder, the renderer skips double vision; above zero without powder, doubleVisionEffect blends the base image with a copy at alpha min(0.5, 0.1 + 0.1 × alcohol level in per mille): each 0.1‰ adds 0.01 to the base alpha of 0.1. For example, 0.2‰ gives alpha 0.12, and 2‰ gives 0.3. From 4‰ onward, alpha stays at 0.5. The copy's center follows a circle around the window center, without rotating the image's orientation. One orbit takes 8 s of active gameplay, and the radius grows linearly by 12 px per 1‰ at 720p, scaling with the shorter window dimension. UV offsets are calculated separately for each axis, preserving a circular orbit even in portrait orientation. The original uses PointClamp; the copy uses LinearClamp for smooth subpixel movement. Outside the shifted copy, the shader leaves the original unchanged, without stretching edges. When RainbowActive is set, a second rainbowEffect pass applies a rainbow gradient to the entire world image before the UI is overlaid. The shader returns a color and alpha 0.22; BlendState.NonPremultiplied blends it with the image. Hue depends on UV.x + 0.5 × UV.y − Phase, and Phase on PlayTime modulo 6 seconds. This shader uses no additional buffer or texture sampling. The rainbow also works at 0‰; active powder blocks both effect passes. Finally, Present overlays the UI buffer using AlphaBlend (premultiplied colors), without a shader. Core then draws the Debug ImGui inspector on the back buffer, outside all gameplay effects. The counter, buttons, pause panel, and game-over panel retain their color, sharpness, and position; world color fading also leaves the UI unaffected. DuiGame.UpdateDisplay sets Cursor.TransformMatrix=ScreenToRaster; Gum divides the transformed position by zoom 4. GameController maps mouse/touch input through ToGamePosition to the playfield. UI and gestures target the same image point after resizing as well. Collisions always use the 1280×720 coordinate system. The logical size of cars and items is 80; swaying, hops, car enlargement, and item pulsing do not change collisions. Walls use the 74×36 footprint; radii are 40 for collection, 20 for items, and 32 for car collisions with the tail.
  14. Exit: the system button closes the desktop window. GameScene.UnloadContent disposes the BeerBurst texture, the grid texture through ParkingLot.Dispose, and calls CarConvoy.Dispose, which disposes the PoliceLightbar texture. GameScene also disposes its watched grayscale material; DuiGame disposes both RetroRenderer buffers and its two watched materials. Core disposes the scene, content, audio, SpriteBatch, and ImGui renderer/context. Program disposes the content watcher. There is no return to a title screen.

Classes and types

Type and sourceResponsibility
DuiGameStarts GameScene without a menu and loops Audio/theme music as a SoundEffect at SongVolume=0.35. After updating the scene, synchronizes SongPlaybackRate with GameScene.MovementSpeedMultiplier; sets 60 Hz, a 320×180 Gum layout at zoom 4, and the cursor transform. Creates watched doubleVisionEffect and rainbowEffect materials. Owns RetroRenderer, wraps DrawScene with it, and passes ScorePermille, PlayTime, and both effect flags. Runs BeginUiFrame and GameScene.DrawUI between drawing the world and Present. Disposes the renderer and its buffers/materials. Owns the game-specific Display mapping. Handles losing and regaining focus.
MaterialOwns a watched Effect, parameter cache, override flag, and registration in s_materials/s_debugMaterials. Reload preserves compatible parameter values and frees the old effect. ImGui exposes numeric properties and texture previews. Dispose unregisters and releases the watched asset.
WatchedAsset<T>Owns isolated content managers for the current and temporarily retained previous asset. Polls file timestamps; loads candidates before swapping. Failed reload retains the last usable asset and reports LastReloadError. Caller owns disposal.
ContentManagerExtensionsWatch and WatchMaterial return caller-owned wrappers; TryRefresh validates ownership. StartContentWatcherTask starts only in Debug/source checkouts unless --no-reload is set.
ContentWatcherLocates the entry project's source, starts dotnet watch for BuildShaderContent, and terminates its child tree on disposal/process exit. No game-specific paths or source dependencies.
ImGuiRendererOwns the ImGui context, font texture, GPU buffers, BasicEffect, rasterizer, and text-input subscription. BeforeLayout handles repeated fixed updates and input capture; AfterLayout renders once on the back buffer. Texture IDs are reused and disposed previews are removed. Dispose releases owned resources and unsubscribes input.
DrawVertDeclarationDescribes ImGui vertex position, UV, and color for the MonoGame graphics pipeline.
ShaderTestGameA separate GPU test host referencing MonoGameLibrary only. Checks live shader replacement, numeric/texture preservation, independent instances, invalid-XNB recovery, cache changes, ImGui rendering, repeated binding and disposal.
AudioControllerOwns a separate looping SoundEffectInstance for music and a list of effect instances with their base volumes. SongPlaybackRate (0.5–2×) changes Pitch=log2(rate) without restarting. SongVolume and SoundEffectVolume control separate channels; MuteAudio/UnmuteAudio preserve both levels. Pausing and resuming preserve position and speed; stopped sounds are not resumed. Update disposes finished effects, and Dispose releases all instances; SoundEffect buffers belong to ContentManager.
CircleA circular collision area with a strict intersection test, as in the tutorial.
CoreOwns MonoGame services, the active scene, and the Debug ImGui renderer. Updates input, watched materials, the ImGui frame, and then the scene. Draw invokes the virtual DrawScene before rendering the debug overlay. F12 toggles the overlay; DebugWantsMouse/Keyboard expose input capture. Disposes services and the ImGui context on exit.
AnimatedSpriteAdvances the current animation frame based on GameTime.
AnimationA list of atlas frames and the duration of each frame.
GameDisplayDefines the 1280×720 playfield and raster and the logical 320×180 UI layout at zoom 4. Resize fits OutputBounds to the entire window, independently on both axes; ScreenToRaster maps the Gum cursor, and ToGamePosition maps gestures to the playfield. Small windows scale the image down.
C64Palette16 Pepto PAL colors in VIC-II order. Supplies black for the presentation and white for small PoliceLightbar highlights, Orange and Yellow for the UI theme, and LightGray (index 15, #959595) for unfilled ScoreStars; inspires artwork colors without restricting the entire frame's colors or bright flash colors.
RetroRendererOwns two 1280×720 RenderTarget2D buffers. BeginFrame clears the world buffer; BeginUiFrame clears the separate UI buffer to transparent. Present scales the world with PointClamp, applies effects, and finally composites the UI through AlphaBlend and PointClamp without effects. At a positive alcohol level, doubleVisionEffect adds a linearly filtered copy with alpha starting at 0.1 and increasing by 0.01 per 0.1‰ (maximum 0.5 from 4‰), with its center moving in a circle. Radius increases with alcohol level and the shorter window dimension; phase depends on PlayTime. At 0‰, the double-vision shader is skipped. When RainbowActive is set, an additional pass applies a moving rainbow at alpha 0.22. VisualEffectsSuppressed skips both effects. Dispose releases both buffers and both watched materials. Parameter setters respect DebugOverride, and texture bindings remain active.
SpriteDrawing parameters for a texture region: position, scale, rotation, color, and layer.
TextureAtlasLoads an XML definition, texture, regions, and animations; creates sprites.
TextureRegionA rectangular atlas region with UV coordinates and a drawing operation.
TilemapLoads a generic tileset and tile grid from XML; draws tiles using the configured tile size and scale. Contains no parking or DUI rules.
TilesetDivides a texture region into tiles, accounting for their size and spacing.
GamePadInfoStores gamepad state and detects new button presses and stick directions.
InputManagerUpdates keyboard, mouse, and four gamepads before updating the scene.
KeyboardInfoStores current and previous keyboard states; detects individual presses.
MouseButtonMouse button names used by MouseInfo.
MouseInfoStores mouse state, position, buttons, and changes since the last update.
SceneOwns the scene's ContentManager; defines initialization, updating, drawing, and resource disposal stages.
KeyboardSteeringA buffer of up to eight directions from arrow/WASD KeyDown/KeyUp events, in arrival order. Preserves brief presses between updates and ignores automatic repeats and other keys. TryReadDirection retrieves each command once. Reset removes pending commands and rebuilds the held-key set from KeyboardState after changes to game state or window focus.
GameControllerInitialize/Shutdown connects and detaches window KeyDown/KeyUp events. KeyboardSteering stores keyboard presses in event order. Update reads the controller and gesture; TryReadDirection drains the keyboard buffer, then passes the controller or gesture direction. ResetInput clears input and synchronizes held-key state. Also handles pausing.
BeerBurstEmits 44 drops and foam puffs at the bottle's collection point. Particles fade after 0.5–0.75 s; the limit is 176. Owns and disposes a one-pixel texture. Particle state contains position, velocity, age, lifetime, size, color, and particle type.
PickupStores sprites for five item types. Spawn selects the type, sets the position, chooses a random velocity, and resets the pulse. Moves the active item by 0.5 units per update, bounces it, and pulses its scale around its center. All types have a fixed collision radius of 20.
PickupTypeItem type: Beer, Vodka, Powder, Mushroom, or Sausage.
PickupRulesChooseType randomly selects beer 50%, vodka 20%, powder 5%, mushroom 5%, and sausage 20%. ApplyScore changes the alcohol level by +0.2/+0.4/0/0/−0.4‰, with a minimum of 0. GrowsConvoy lengthens the convoy after drinks and powder.
PowerupEffectsOwns independent 10-second powder and mushroom timers. PowderRemaining and MushroomRemaining expose timers to UI indicators. Collect refreshes the duration. MapDirection reverses input while a mushroom is active. VisualEffectsSuppressed hides effects after powder, and RainbowActive accounts for both timers. Update counts down normal time and returns movement time scaled for the parts of the frame covered by effects: powder 1.2×, mushroom 0.5×, both 0.6×. MovementSpeedMultiplier exposes the current speed for music using the same constants as Update. Carries over tenths of a tick; Reset removes both effects and the time remainder, restoring the 1× multiplier.
ScreenShakeTimes 3 seconds of visual playfield shaking: ±24 px at 18 Hz. RemainingTime exposes the remaining duration to the vodka indicator. Restart refreshes the duration, Update measures active gameplay, and Reset turns the effect off. Does not manage the UI or physics.
CarHopState of a single car hop. Advance detects the front crossing a curb using two consecutive CarPose values and grass rectangles. Remembers the start time and readiness for re-entry. GetTransform(RenderTime) returns a 1–1.28 multiplier and 0–12 px lift over 200 ms. EaseOutCubic controls takeoff, and EaseInQuad controls landing.
CarSwayA pure CarPose → CarPose function adding visual displacement of ±1.5 px and rotation of ±2°. Phase depends on distance, so each segment repeats the head's sway; the period corresponds to 1.2 s. Does not change the model or collisions.
Easings31 static float → float functions: Linear and 30 curves from easings.net. Input progress is 0–1; Back and Elastic retain overshoot beyond this range. EaseOutCubic and EaseInQuad control takeoff and landing. Driving arcs are geometric and do not use easing functions.
CarConvoyConnects ConvoyMovement to rendering and ParkingLot. SegmentCount reads the number of Cars, including the head, for scoring. Update accepts movement time already adjusted by PowerupEffects. Owns each car's CarHop state and previous pose. After every substep, updates hops and checks the fence and gate through ParkingGeometry using the head's center and rotation. Draw retrieves the interpolated pose and adds CarSway, grass scale, and the hop. Draws index 0 as the player's car and the others as police cars with PoliceLightbar lights. Dispose releases the lightbar resource; car textures belong to ContentManager. Forwards BodyCollision and BoundaryCollision to the scene; GetBounds keeps a 40 px radius for bottle collection.
PoliceLightbarDraws a pixel lightbar in the police car's local coordinates. Exactly two 250 ms frames: opaque 8×12 lamps in bright blue or red, with a 2×2 highlight. C64Palette supplies black for the frame and white for the highlight. The frame depends on the model's RenderTime. Shares the car's rotation, scale, and lift. Owns a one-white-pixel texture; CarConvoy.Dispose releases it.
ParkingLotOwns the Tilemap using c64-parking-atlas, the c64-storefront facade, fence regions, geometry for two grass islands, and a one-pixel grid texture. DrawGrid draws gray lines every 80 px (GridLineWidth=1, GridOpacity=0.35) within the driving area, below sprites, without doubled alpha at intersections. Dispose releases only its own grid texture. DrawStorefront scales the source uniformly to 480×160 in the center and fills the sides with a repeated display segment; it does not squeeze the image to the full strip's proportions. DrawFenceCorners assembles mirrored corners from a horizontal half-span, a vertical section, and a bracket. Sets the 80×80 tile size, game start position, and ParkingGeometry; exposes DrivingBounds and PickupBounds. GrassIslands exposes a read-only view of rectangles for CarHop; GetCarScale calculates terrain enlargement up to 106%.
ParkingGeometryCollision geometry matching the parking lot artwork at an 80×80 tile scale. DrivingBounds reaches the fence's inner edges; GateBounds describes the protruding closed gate. IntersectsBoundary checks both areas through ConvoyCollision. PickupBounds defines a rectangular area for item bounces and respawns, ending before the gate.
ConvoyMovementA movement model along tile-center axes: 400 px/s, tangent 90° arcs with a 40 px radius (about 157 ms), and two pending directions. The constructor snaps the start to a tile center. Turns begin at tile edges or up to 20 px beyond them (TurnGraceDistance). Late input reduces the arc radius to 20–40 px; the car starts the maneuver at its current position and ends exactly on the next axis. Later input waits for the next edge. AdvanceHead splits the 5 ms substep at arc boundaries; AdvanceTurn calculates position and tangent from path length. Preserves leftover time and visual interpolation. Cars exposes current CarPose values, and GetRenderPose provides drawing poses. Cars replay the trail at 80 px intervals. Stepped synchronizes terrain and boundary checks; BodyCollision stops the simulation. Stop also interrupts the rest of the update.
CarPoseImmutable car center in playfield pixels, rotation in radians, and distance along the head's trail. Interpolation accounts for angle wrapping.
ConvoyTrailHead position history indexed by distance. Uses binary search and interpolation for segments; retains the convoy length plus room for a new car. Compacts the buffer in batches. Extends a missing start of the history backward along the oldest direction.
ConvoyCollisionIntersection of moving car circles with a 32 px radius in relative space, including between substep endpoints. Checks parking boundaries against a rotated 74×36 px car footprint. IsOutsideParking accepts CarPose, and the extreme coordinates depend on the car's length, width, and current angle. IntersectsObstacle checks the rotated car and gate rectangle on four separating axes.
SwipeTrackerRecognizes one direction per contact after a movement of 32 playfield units; ignores edge tiles and the score bar.
GameSceneManages Playing/Paused/GameOver state, collisions, the decimal alcohol level in per mille according to PickupRules, the Score read from CarConvoy.SegmentCount, random item selection, Pickup respawns and bounces within ParkingLot.PickupBounds, beer splashes, and UI panels. Loads collection effects for five PickupType values (shared eat for mushrooms and sausages), plays the collected type's sound before item respawn, and plays crash only on the Playing → GameOver transition. Exposes MovementSpeedMultiplier for music, plus VisualEffectsSuppressed, RainbowActive, ScorePermille, and PlayTime, which advances only while Playing and resets on RETRY, for double-vision presentation. Connects ParkingLot to CarConvoy drawing and collision checks. Owns PowerupEffects, maps directions and movement time through it, and passes flags to the renderer. Owns and disposes the watched grayscale material; its numeric setters respect inspector overrides. Skips Gum input while ImGui captures the mouse or keyboard. Owns ScreenShake, updates it while Playing, restarts it after vodka, and resets it on RETRY. Draw renders only the world with the shaking offset (zero during powder) into the RetroRenderer buffer. Separate DrawUI passes current timers to UpdateEffectIndicators and Score to UpdateScoreStars, then draws Gum into the layer overlaid after all world effects.
C64ThemeShared Fonts/c64.fnt font and central color roles for the entire UI: background, text, accent, pressed state, muted elements, and symbols. The current variant uses Orange for the background, Yellow for text and accents, White for pressed states and symbols, and LightGray for muted elements. ApplyFont sets bitmap characters, scale, and TextColor. CreateSurface creates a flat RectangleRuntime; AddFrame combines an AccentColor border and BackgroundColor background, without extra textures or disposable resources. Used by the HUD, both panels, C64Button, indicators, and ScoreStars. A new variant requires changing assignments and recreating the UI.
C64ButtonA Gum button with a rectangular border and C64 font. Replaces default ButtonVisual children and overrides all states. Focus and hover use BackgroundColor on AccentColor; pressing uses PressedColor. All states get colors from C64Theme. Supports mouse, touch, keyboard, and controller input, preserving left/right navigation and focus on hover. Does not use the tutorial atlas or animations.
ScoreStarsA container for five SpriteRuntime pairs: a light gray background (C64Theme.MutedColor) and white fill (C64Theme.SymbolColor). UpdateScore clips layers to whole texture pixels according to the segment count (including the head), within a 0–84 range. Gaps of 2 UI units do not count toward progress. Total width is 43 units and height is 7; at zoom 4, this gives 172×28 px. Remembers the last clamped value and changes clipping only when the score changes. The shared score-star.png texture belongs to Gum's ContentManager. Owns no timer or disposable resource.
GameSceneUIFormats the alcohol level with one decimal place (pl-PL), drawing the number and ‰ sign together through TextRuntime with the C64 font. Positions icon and star slots according to text width in the logical 320×180 layout, drawn at zoom 4 in a separate transparent 720p buffer without a border, overlaid after world effects. Owns three SpriteRuntime indicators in a fixed order after the ‰ sign; UpdateEffectIndicators calculates 300/300 ms blinking, accelerated to 100/100 ms during each effect's last second, from the models' remaining times. Also owns ScoreStars; UpdateScoreStars passes the segment count. PositionScoreAccessories moves slots and stars after the alcohol counter. Icons use separate white 28×28 UI textures with transparency, tinted by C64Theme.SymbolColor; they belong to Gum's ContentManager. Builds the HUD bar border and both panels through C64Theme. Draws C64Button buttons: PAUSE, RESUME, and RETRY. Events go to GameScene.

Car assets

The player uses car.png, and the tail uses police-car.png. Both sprites were redrawn with the built-in image_gen as simple icons with a composition of roughly 24×24 logical pixels: large color blocks, solid windows, simple wheels, and a single shadow. No reflections, inner outlines, or fine details. Textures remain at full size; they are not filtered or automatically pixelated. The police car has silver-blue panels without small lettering. They retain their size, right-facing orientation, and transparent backgrounds. Lights are not stored in the texture: PoliceLightbar overlays a two-state animation on the blank roof. The full prompt and reference source are in AssetPrompts.json.

Parking lot assets

The map definition uses the 4×4 C64 atlas: 0 asphalt, 1–3 parking lines, 4–9 grass edges, 10–11 vertical fencing, 12 and 15 horizontal fencing, 13–14 the closed gate. Regions are 306×306 pixels, with spacing 8 and origin (4,4), excluding the sheet's divider lines. The C64 storefront covers the top two rows, and the UI has its own C64 font atlas and borders drawn with rectangles. Tiles appear at 80×80 pixels, and the storefront strip at 1280×160. The central 2172×724 image is drawn at 480×160 with the same scale on both axes. Region (26,0,432,724), cut through the gray pillars of the first display bay, repeats from the central facade toward both screen edges. The sign and doors appear only once, with partial sections at the image edges. Textures retain their colors without palette reduction. Two-color 2×2 checker patterns and sparser pixel accents form part of the textures' materials and shadows. Each display section has 12 slender bottles. Their side edges alternate pixels with a similar, darker shade of the same color, for example red #9A6759 with #805247, without black notches; the center remains solid. Patterns are part of the texture, and uniform scaling preserves their proportions. Both variants were edited with the built-in image_gen; the originals remain as source material. Corners use the top 100 rows of tile 10 and the right half of tile 12. Both fragments keep the atlas scale, so rails and mesh patterns match the straight spans. Only the metal bracket comes from separate artwork: region (544,510,205,245) is drawn at 14×23 at position (34,25) inside the left corner tile. The right corner is a horizontal mirror of the entire joint. ParkingGeometry accounts for metal positions within tiles: side edges are inset 46 px from the playfield sides, the horizontal span starts 26 px below the top of the bottom row, and the gate 14 px below it. Prompts for new artwork are in AssetPrompts.json.

Collectible bottle asset

beer-bottle.png has a simple silhouette made of large blocks, amber glass with one darker edge, a flat cap, and a cream label with a red band. It has no gloss, small highlights, or lettering. It was redrawn with image_gen; Pickup retains its scale, pulsing, and collision radius of 20. The prompt is in AssetPrompts.json.

New item assets

vodka-shot.png, sausage.png, powder-bag.png, and mushroom.png are separate transparent sprites generated with the built-in image_gen. Prompts are recorded in AssetPrompts.json. Content.mgcb builds them as straight-alpha textures; GameScene loads them for Pickup. All types share the same logical 80×80 square and collection radius of 20.

Effect indicator assets

Separate white UI sprites: shot glass, bag, mushroom. Each is 28×28 px, using only white and transparency, without shades or a colored outline. Sources are hand-drawn pixel rectangles on a 14×14 grid: vodka-indicator.svg, powder-indicator.svg, mushroom-indicator.svg. Rasterization enlarges each pixel by exactly 2× without antialiasing. GameSceneUI loads the textures through the main ContentManager; playfield item artwork remains separate.

Score star asset

score-star.png is a white 28×28 px pixel star with binary transparency. The score-star.svg source uses rectangles on a 14×14 grid, enlarged 2× without antialiasing. Content.mgcb builds it with premultiplication, without mipmaps or resizing. ScoreStars uses the same texture for the C64Palette.LightGray background and white fill; SpriteRuntime supplies the color.

C64 font and UI theme

c64.fnt and c64.png form a bitmap font. The source is C64 by zeiche under CC0; the source and generation notes, license, and TTF are preserved in SourceAssets/Fonts. build_font.py requires Pillow only to rebuild the asset. It generates an 8×8 grid without antialiasing, ASCII 32–95, and an additional 12×8 ‰ glyph. Content.mgcb copies the FNT and license and builds the texture with premultiplication. Gum's ContentManager owns the texture; there is no system font dependency. The tutorial UI atlas, 04b_30, and separate ‰ sprite have been removed. C64Theme draws borders with rectangles, and C64Button assigns colors to all input states. Custom white icons and stars remain separate textures.

Audio assets

The audio sources and preparation notes describe the CC0 recordings: Joseph SARDIN's burp, Sadiquecat's short male “ahh” (0.55 s), OwlStorm's sniff, Tito and StarNinjas' eating sounds, and squareal's crash. build_audio.py trims them, filters them, fades their edges, and normalizes peaks to −3 dBFS; it writes mono 16-bit 44.1 kHz PCM. It also converts the supplied MP3 to stereo Vorbis as theme.ogg. The music has a separate origin from the CC0 effects. Content.mgcb builds five new WAV files and the track through SoundEffectProcessor and copies credits.txt into the release. Audio/theme.xnb contains about 22.2 MiB of stereo PCM, loaded once; speed changes do not decode or create copies of the track. A separate streamed OGG file is not required; scripts/release.py accounts for the processor type during release validation. The old shared collect.wav has been removed; ui.wav and bounce.wav remain.

Verification and limitations

DUI.Tests runs 67 tests without a GPU. MovementTests checks waiting for a tile edge, commands beyond the tolerance, 500 turns without leaving the grid axes (logical and rendered state), four directions, constant speed, the queue, rejection of reversals and repeats, leftover time, interpolation, the trail through four turns, spacing, growth, bounded history, tight U-turns, collisions between substep endpoints, parking boundaries, stopping, pausing, and restarting. Six SteeringTests check immediate turns when 2, 10, and 20 px late in both directions, constant speed without teleportation, return to the correct axis, police car trails and spacing, and independence from time partitioning. They check brief arrow/WASD presses between updates, event order, sequence reversal by a mushroom, suppression of automatic repeats, and reset after focus loss. CarAnimationTests checks sway bounds, hops from four sides and diagonally, active animation, driving on grass and leaving it, re-arming after leaving the island, segment delay on a turn, pausing, restarting, and independence from time partitioning. Other tests cover gestures, screen mapping, and Circle. Four tests in WallCollisionTests reproduce a false collision during a tight turn and check convoy travel along all four walls, including late turns with police cars throughout the tolerance window and in front of the closed gate, the extreme sides and corners of a rotated car, and stopping after a late command beyond the last safe turning edge and its 20 px tolerance. They use the same ParkingGeometry boundaries as the game. Four tests in ParkingGeometryTests check driving on asphalt within fence tiles, the absence of false collisions when an angled car passes gate corners, separate gate and fence-span edges, and the bottle bounce and respawn area before the closed gate. Three GameDisplayTests check full window coverage without borders or playfield cropping, agreement between UI mapping at zoom 4 and gestures on both axes after resizing, and rejection of gestures from the HUD or outside the playfield. They cover wide, portrait, odd-sized, and smaller-than-raster windows. Three PickupTests check the 50/20/5/5/20 distribution, mixed alcohol level changes, growth, and the 0‰ lower limit after a snack. Four ScreenShakeTests check 18 Hz and ±24 px, the 3-second duration, frozen phase, reset, refresh, and time partitioning. Fourteen PowerupEffectsTests check all directions, 10-second durations, refreshing, effect overlap, reset, time partitioning, and 480, 200, and 240 px/s, car spacing, normal timer speed, independent multiplier expiry in both orders, the part of a frame after expiry, and fractional ticks. Three music-speed regressions compare MovementSpeedMultiplier with actual car movement, check refresh, pause, and reset, and verify the current multiplier after expiry rather than the previous frame's average. Release tests check that a track built through SoundEffectProcessor requires only an XNB, while SongProcessor also requires a separate audio file. Tests reference the actual DUI.Game and MonoGameLibrary assemblies, including internal game types through InternalsVisibleTo.

The Desktop builds workflow runs the same suite on Windows, Linux, and both macOS architectures; CI results do not verify GPU behavior or launching the downloaded app from Finder.

MonoGameLibrary.Tests is an explicit Debug GPU suite referencing only MonoGameLibrary. Run it with the desktop build's Content directory. It renders the inspector and checks scalar/vector/texture preservation, failed-XNB recovery, changed parameter interfaces, independent material ownership, deduplicated texture bindings, and disposal. The automatic .fx build watcher and F12/Gum input boundaries also need a running-game check.

Tests do not replace checks of window KeyDown/KeyUp events, rapid arrow/WASD sequences, buffer reset after pausing, focus loss, and RETRY, tighter turns up to 20 px past an edge, rendering, looping the new music and balancing it with effects, 1.2×/0.5×/0.6× speed and pitch changes without restarting, independent effect expiry, returning to 1× on RETRY, separate volumes and muting both channels, burps after beer, exhales after vodka, sniffs after powder, eating after mushrooms and sausages, a single crash sound for wall and tail collisions, Gum buttons, driving along row and column centers, smooth arcs and their replay by the tail, joins between parking, storefront, fence, and gate tiles, the gray 80×80 grid on asphalt and grass (alpha 0.35 without stronger intersections, clipped to the driving area and gate, below sprites), car swaying and segment delay, police cars in the tail and two light colors on rotating roofs, each car enlarging on grass and hopping on entry, bottle pulsing and collection, beer splashes, alcohol changes of +0.2/+0.4/−0.4‰, growth after drinks and powder, both powerups lasting 10 seconds, input reversal, 1.2× acceleration, 0.5× slowdown and the combined 0.6× multiplier, shaking only the playfield for 3 seconds after vodka and resetting to 0,0‰, sprite position during the 9,8‰ → 10,0‰ transition, and focus loss in the running app. The double-vision shader requires GPU checks: no effect at 0‰, alpha increasing by 0.01 per 0.1‰ from a base of 0.1 and capped at 0.5, growing radius, a circular orbit at different window aspect ratios, a sharp original and smooth copy, image edges, pausing, and RETRY. The rainbow requires checks of its spatial gradient, movement over time, alpha 0.22, combination with double vision, and suppression of both shaders and shaking after powder. Separately compare UI pixels with an active rainbow, double vision, shaking, and world fading: HUD, PAUSE, RESUME, and RETRY must retain their colors and positions. Also check indicator activation, both blinking phases (300/300 ms, then 100/100 ms in the final second), refresh, overlap, and expiry, pausing, RETRY, and positioning after a 9,8 → 10,0 change and with a three-digit alcohol counter. Check stars for every score from 0–84, a visible increase with each segment, 42 as 2.5 stars, 84 and above as all five filled, a point for the head after RETRY, growth only after beer/vodka/powder, and behavior during pause and game over. Confirm pixel-by-pixel clipping without stretching, fixed slots despite blinking powerups, and no overlap with PAUSE after the alcohol counter widens. Check the C64 font in the counter and headings, the ‰ glyph, exact Orange/Yellow colors, all button states, PAUSE/RESUME/RETRY clicks, and keyboard confirmation. Check transparent edges, the absence of a UI copy in the world, and scaling of both layers in wide, portrait, odd-sized, and smaller-than-raster windows. A physical phone version, safe areas, and behavior after process loss are outside the desktop target; mobile hosts are not planned.
